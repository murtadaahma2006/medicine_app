# سجل المؤجّلات والتحسينات المتراكمة (Backlog)

> مرجع دائم للبنود غير الحاجبة المؤجَّلة عمداً. تُراجع عند بداية كل مرحلة، ويُنفَّذ البند عند أول لمسة للملف المعني.

## 1) tts_service.dart — تحسينات (مسجّل من qa-tester)
- **Completer للتهيئة**: نداءان متزامنان لـ speak/ensureInitialized قد ينفذان التهيئة مرتين (لا قفل). Completer واحد يجعلها محكمة.
- **عداد فشل**: عند غياب المحرك يعيد كل speak محاولة البناء. عدّاد يوقف إعادة المحاولة بعد N فشل.
- **إعادة ضبط السرعة في speakItem** (من مراجعة المرحلة الرابعة): تُنفَّذ فوراً بعد speak بافتراض أن flutter_tts يقرأ السرعة لحظة الاستدعاء فقط. لو ظهرت سرعة خاطئة في نطق متتابع سريع: أعد الضبط عند حدث completion بدل الفوراً.
- **التوقيت**: أول لمسة لـ tts_service في أي مرحلة قادمة.

## 3) قرار لغوي معلّق — صف «ch» في الدرس 3 (من qa-tester)
- tts_text الحالي «ach» ينطقها المحرك [ax] عميقة، بينما المثال التوضيحي للصف «Ich» بصوت ch اللين [ç] — الطالب يسمع العميق مع مثال اللين.
- التوصية: تغيير tts_text إلى «ich»، بالترتيب: خبير المحتوى يحدّث docs/content_a0_unit1.md أولاً ← ثم الزرع ← ثم الاختبار.

## 4) كفاءة _insertOrIgnore عند توسيع المنهج (من qa-tester)
- SELECT COUNT قبل/بعد كل صف = ~104 استعلاماً لكل تشغيل أول؛ مقبول لحجم الوحدة الواحدة. عند توسيع المنهج: انتقل إلى db.rawInsert وإقراء rowid أو RETURNING.

## 6) writing_corrector.dart — ملاحظتان اختياريتان (من qa-tester، مراجعة م6)
- **_eiIeSwapped** تستخدم replaceAllMapped شاملاً: كلمة مثل «eiei» مقابل «ieie» تحصل تشخيص ei/ie رغم أنه تبديل موضعين (يبقى مرفضاً — التأثير تشخيصي فقط). أعد النظر إن دخلت كلمات مركبة.
- **commonMisspellings['morgen'] = "morgan'"** صف ميت عملياً: الاقتباس الختامي لا يدخل نطاق regex الترقيم فلن يُقص أبداً فلا يطابق. احذفه أو وثّق سببه عند أول لمسة للملف.
